# llm/engine/pin/index.txt -- xollama's index of the pinned opencoti engine.
#
# opencoti pin format 2 (their docs/protocols/PIN_FORMAT.md). This file is
# OURS: it names the components this tree takes, each by the commit its pin
# file is readable at, the sha256 of that pin file and its version. The pin
# files beside it are opencoti's, vendored byte-identical; never edit one.
# A file name is unique across the components (BUILD_INFO.<component>.md).
#
# Read by llm/engine/pin.go (embedded) and cmake/opencoti-fetch.cmake (build
# time). Both refuse a vendored pin that is not the one named here, and a
# component whose abi or engine-min the engine does not meet. The engine and
# everything beside it is fetched ONCE, at build time; xollama never downloads
# an engine at runtime.
#
# Moving a component is one line here plus its pin file, on a MEASUREMENT
# (scripts/phase2-engine-ab.py, as the `ollama` user), never on a changelog.
#
# THIS PIN (2026-10-13, opencoti mail #1221; index 7b442d0b, pins 15756eb9,
# payload c098ced8): opencoti's c11 RELEASE, re-cut r5. Only the engine's
# bytes differ from r4 (engine 2610130541001; every library is the same file,
# its pin has the new payload commit and, for cuda, vulkan and macos, the r5
# engine in `gated-with`). r5 = r4 + 0648 (bug-4048): on Metal, c11 handed
# the recurrent op of the Gated Delta Net (Qwen3.5 / 3.6 / 3.8 and their
# merges) raw gates its kernel has no activation code for. Sampled, such a
# model repeated one token to the limit; greedy, the engine threw
# `got exception: vector`. Every macOS release from v0.40.2-xollama to
# v0.40.3-xollama.1 has it.
# MEASURED through xollama on the Mac mini (M4, 24 GiB): the released
# v0.40.3-xollama.1 payload with only the engine file replaced, four sampled
# 512-token runs and one greedy run per model (scripts/gates/bench.sh).
# r4: qwen3.5:2b fails every request. r5: qwen3.5:2b 64.7 tok/s, qwen3.5:9b
# 26.2, mannix/omnimerge-v4-mtp:IQ2_M 9.8 to 10.8 (loaded alone), all five
# runs each with real text; qwen2.5:1.5b 124 and llama3 31.9 unchanged.
#
# THE r4 PIN (2026-10-11, opencoti mail #1103; index a2a0a0d6, pins 4965d9c5,
# payload f28ab19d): opencoti's c11 RELEASE, re-cut r4. Only the engine's
# bytes differ from r2 (engine 2610111946001; every library is the same file,
# its pin has the new payload commit and, for cuda and vulkan, the r3 and r4
# engines in `gated-with`). r4 = r2 + 0618 (drafter_state_v1, a new feature
# row), 0619 (bug-4002, a wake fix) + 0635 (bug-4030): under --kv-unified the
# context checkpoint of an iSWA model's KVarN cell ring was written in a form
# the reader could only place by luck, so a rewind past the sliding window
# failed with "KVarN selective state is missing a required live stage row"
# and re-read the whole prompt (pandorum, 32 of 41 restores, 2026-10-11).
# MEASURED through xollama on the 3090 (gemma4:e4b, kvarn3, unified, 4 slots,
# 96000, batch 512, opencoti's five-request shape): r2 fails both restores and
# re-reads 54784 and 50220 tokens; r4 restores both and re-reads 13185 and
# 301. After a restore the greedy continuation can differ from a full re-read
# in its first token (opencoti's known near-tie residual, fixed in c12).
# r3 (engine 2610110544001) was never pinned here.
#
# THE r2 PIN (2026-10-10, opencoti mails #950, #956; index 322fae03, pins
# b14e609d, payload 455b729b): opencoti's c11 RELEASE, re-cut r2. Every
# component but media moved from c10 (media is the c10 r3 file set); the ggml
# ABI is ea73e6b2 on the engine and every GPU library, so a c10 library is
# refused by name. It carries 0589 (bug-3957, the per-device KV window on a
# two-GPU split) and 0610 to 0612 (bug-3993, bug-3995: a KVarN record window
# sized against what an assistant drafter takes, and the drafter dropped at
# load when keeping it would push the KV cache off the card; our bug-260).
# r2 is the first cut (engine 2610100940001, index 6170b522) plus 0613: that
# engine aborted loading Qwen3.5 0.8B/2B/4B when the fit streamed a host tail
# (bug-3999, found by our G3: qwen3.5:2b with 2.4 GB of the card free). Only
# the engine's bytes differ between the two cuts; the libraries are the same
# files, their BUILD_INFO texts gained the r2 engine in `gated-with`.
#
# `sbsa` is TAKEN from this pin on (owner, 2026-10-10: "we build it blindly,
# untested"): ggml-cuda-sbsa-aarch64.so, CUDA 13 for Linux aarch64, sass 110
# 121 (Jetson Thor, DGX Spark). opencoti's BUILD_INFO says it was never run,
# and no such machine is in our fleet either. It is routed with its own sass
# list (Pin.SBSASASS, HostCUDASASS).
#
