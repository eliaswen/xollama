---
title: What xollama adds
---

xollama is a soft fork of Ollama. It runs everything Ollama runs, the same way,
and adds a few things on top: **council chat**, where one model name answers
with a planner, researchers, critics and a synthesizer; **image, speech,
transcription and video models** on OpenAI's routes; a way to **bound how
long a model thinks**; a **tokenizer endpoint**; **speculative decoding with a
Gemma-4 assistant drafter**; and the option to serve GGUF models on a
**different inference engine**, opencoti-llamafile, instead of stock
`llama-server`.

<Note>
  **Off means off.** With `XOLLAMA_ENGINE=llamacpp` and no fork settings,
  xollama behaves identically to the Ollama release it is built from. Every
  feature on this page is something you switch on.
</Note>

## The additions

| | What it is | Where |
|---|---|---|
| **Council chat** | One model name that answers each turn by planning, researching and critiquing in parallel, then synthesizing — through every chat API, with the deliberation shown as thinking | [Council chat](/xollama/council) |
| **Images, speech, transcription, video** | Media models served on OpenAI's image, audio and video routes: pull one, or add media to a chat model | [Images, speech, transcription and video](/xollama/media) |
| **Think budget** | Cap the tokens a reasoning model may spend inside its thinking block, per request or per model, so it answers instead of looping until the context is gone | [Bounding thinking](/xollama/think-budget) |
| **`/api/tokenize`** | Count or inspect tokens with the model's own tokenizer, without generating | [Tokenizer endpoints](/xollama/tokenize) |
| **Gemma-4 drafters** | Speculative decoding using a Gemma-4 assistant head as the drafter | [Gemma-4 drafters](/xollama/gemma4-drafter) |
| **Tool-call progress** | A streamed chat reports the tool call a model is still writing, so a client can show it or cut a runaway one | [Tool-call progress](/xollama/tool-call-progress) |
| **Ternary Bonsai 2 27B** | PrismML's ternary 27B model, 6 to 8.6 GB, which stock Ollama cannot load | [Ternary Bonsai 2 27B](/xollama/bonsai) |
| **opencoti engine** | Serve GGUF on opencoti-llamafile instead of `llama-server`, for its KV-capacity and long-context work | [Choosing an engine](/xollama/engines) · [Tuning opencoti](/xollama/opencoti-tuning) |

Models made for these features are in the
[mannix library on ollama.com](https://ollama.com/mannix); the ones that matter
here are listed in [Models for xOllama](/xollama/models).

The think budget and the tokenizer are staged as pull requests against
upstream Ollama and are written to behave exactly as they would if upstream
took them. The others are fork features.

## Environment variables

Every `OLLAMA_*` variable keeps working. xollama also reads an `XOLLAMA_*`
alias for each one, and the alias wins when both are set — so you can run
xollama and Ollama side by side with different settings. An **empty**
`XOLLAMA_*` value does not mask the `OLLAMA_*` one; unset it to fall back.

| Variable | Meaning |
|---|---|
| `XOLLAMA_ENGINE` | `auto` (default), `opencoti` or `llamacpp` |
| `XOLLAMA_ENGINE_PATH` | Path to an opencoti-llamafile artifact, overriding the search |
| `XOLLAMA_ENGINE_FALLBACK` | Retry a failed opencoti load on stock `llama.cpp`. Default `false` |
| `XOLLAMA_SESSION_AFFINITY` | Return a conversation to the slot holding its cache, on opencoti. Default `true` |
| `XOLLAMA_SESSION_POOL` | Share one copy of a common prefix between conversations, on opencoti. Default `false` |
| `XOLLAMA_COUNCIL_HOSTS` | Servers a council role may run on (`council.<role>.host`): host or host:port, comma separated, `*` for any. Default none |
| `XOLLAMA_K_CACHE_TYPE`, `XOLLAMA_V_CACHE_TYPE` | KV cache type per half, overriding `OLLAMA_KV_CACHE_TYPE` |
| `XOLLAMA_K_CACHE_TYPE_SWA`, `XOLLAMA_V_CACHE_TYPE_SWA` | Cache types for a sliding-window model's short-window cache |
| `XOLLAMA_DYNAMIC_SLOTS` | Grow concurrency with demand instead of reserving it. Default `true` |
| `XOLLAMA_MAX_PARALLEL`, `XOLLAMA_SLOTS_TPS_FLOOR`, `XOLLAMA_SLOTS_VRAM_RESERVE` | The ceiling and the two brakes on admitting another request |
| `XOLLAMA_HOST`, `XOLLAMA_MODELS`, `XOLLAMA_DEBUG`, `XOLLAMA_FLASH_ATTENTION`, `XOLLAMA_LLAMA_ARG_FIT` | Aliases for the `OLLAMA_*` variables of the same name |

Run `xollama serve --help` for the full list as your build sees it; every
`tweak` flag is in [Every tweak setting](/xollama/tweak-reference). Anything in that table is a **server-wide** answer; a model
can override most of them for itself — see
[Settings that belong to the model](/xollama/model-settings), and
[`xollama tweak model`](/xollama/tweak) for the command that sets them.
